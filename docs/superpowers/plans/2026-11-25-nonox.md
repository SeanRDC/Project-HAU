# Nonox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nonox, a blue-grey Persian kitten, lives on St. Joseph Hall's ground-floor walkway, wanders it, now and then roams out and comes back, walks up to the student to greet them, and can be petted with E.

**Architecture:** Nonox is one more entry in `critters.gd`'s `cats` array, so he gets the cats' sprite setup, lighting, shadows, the "Hawakan si …" prompt, the bubble, the meow/purr sounds and the E key for free. Only his behaviour is new: a `_update_nonox()` state machine beside `_update_cat()`, a `NONOX` config dict and `NONOX_ROUTES` waypoint lists (there is no navmesh; cats walk straight lines, so every roam is a short list of straight legs, each one checked in `--test`).

**Tech Stack:** Godot 4.7.2 (GDScript), Node for the one-off sheet split.

## Review Focus

1. **Player moves during an approach.** He walks to a fixed stop point; if the student is then more than 3 m from where they stood, he gives up and walks back (Task 3 test: move the student mid-approach → state leaves `approach`).
2. **E spammed.** A second `pet()` within 3 s must not restart the pose or count a pet, but must still return `true` so E/Space don't fall through to anything else (Task 4 test).
3. **Off-screen trips.** `_awake()` freezes off-screen cats; Nonox must keep walking off-screen or he never comes home (Task 3 test: update with the student far away, he still moves).
4. **Free cam (F2).** It calls `critters.update(…)` with the student "still"; Nonox must not approach then (Task 3 test via `_quiet`, and aps.gd's free-cam call passes `talking = true`).
5. **Leaving the hallway by accident.** Wander targets are clipped to `Hallway.in_hall`; after an approach or pet outside it he walks back along the straight line he came by (`left_from`) (Task 2 and Task 4 tests).

- Produces:
  - Routes from home, as straight legs: the first point of each is reached from `NONOX.home`, and the last point is the roam spot.

    ```gdscript
    const NONOX_ROUTES := [
    	[Vector2(0.0, -1.2), Vector2(0.0, 3.0), Vector2(-4.8, 6.0)],   # beside Mingming
    	[Vector2(0.0, -1.2), Vector2(0.7, 5.3)],                       # the APS entrance

    ```

    If a leg fails the check, move that waypoint (the failing route and leg are printed) rather than dropping the check.
  - `func _start_roam(cat: Dictionary, route: int) -> void` sets `away = true`, `route = NONOX_ROUTES[route].duplicate()` and `spot = route's last point`, then enters `walk_route`.
  - `func _go_home(cat: Dictionary) -> void` sets `route` = the current roam route reversed (without its last point) plus `NONOX.home`, sets `away = false`, then enters `walk_route`.
  - `static func _leg_clear(a: Vector2, b: Vector2) -> bool` is `_clear_spot(a, b).distance_to(b) < 0.06`.
- New states:
  - `walk_route`: walks to `route[0]` and pops it on arrival. When the route is empty it enters `idle`; if `away`, it also sets `base = spot` and `cat.stay = randf_range(roam_stay)`. `stay` is a new key, counted down in `idle`/`wander` while away. While `away`, wander targets lie within `away_radius` of `spot` (by `_clear_spot`) instead of inside the hallway. When the stay timer runs out in `idle`, he calls `_go_home`.
  - `roam_t` counts down only in `idle`/`wander` at home. At zero it rolls `roam_chance`: success calls `_start_roam` with a random route, and either way it re-rolls `roam_every`.
  - `approach_t` counts down always. At zero, in `idle`/`wander`, when not `_quiet` and the student is within `approach_range`: let `stop = at + (cat.at - at).normalized() * approach_stop` (the side he comes from). If `_leg_clear(cat.at, stop)`, set `left_from = cat.at` and `target = stop`, and enter `approach`; otherwise re-roll `approach_every`.
  - `approach`: walks to `target`. On arrival it enters `greet`. If the student is more than `approach_give_up` from where they stood when he set off, or he gets stuck, it calls `_walk_back`.
  - `greet`: shows `sheets.front`, faces the student, and on entering plays `sound.meow()` and `_say(cat, "Meow!")`. After `greet_timeout` it rolls `sulk_chance` → `sulk` (shows `sheets.blep` for `sulk_time`), else `_walk_back`; `sulk` then also `_walk_back`. Re-roll `approach_every` on leaving `greet`.
  - `func _walk_back(cat: Dictionary) -> void`: `route = [left_from]`, `left_from = INF`, then `walk_route`. This is the same straight line, so it is clear.
